# Repository instructions

Read `rio-bairros-plan.md` first. It is the product spec and phase plan; Section 2 lists decisions that are settled. If you think one is wrong, say so in the PR description and implement it as written anyway.

## Commands

- `npm run dev` / `npm run build` / `npm run preview`
- `npm test` (Vitest), `npm run lint`, `npm run format:check`
- `npm run build:data` regenerates everything in `data/` from `data/raw/` (geo → exclude → matrix → check:hints)
- `npm run gen:hints` calls the Anthropic API and is run by a human only; never run it, never commit an API key

## Stack, in one line

Vite + React + TypeScript, plain CSS modules, d3-geo rendering SVG. Turf is a build-time devDependency only. No Leaflet, no MapLibre, no tiles, no basemap, no UI library, no CSS framework, no runtime fetch of geometry.

## How work is delivered

- One branch per phase (`phase-N-<slug>`), one PR, at most ~600 lines of diff excluding generated JSON. Split if larger.
- Conventional commits. Do not squash or rewrite pushed history; push follow-ups as new commits.
- Any new dependency is listed in the PR description with a one-line reason.
- Pure game logic lives in `src/game/` with Vitest tests. UI components do not compute distances or colors.
- Every PR description states what changed, how it was verified (tests, lint, Lighthouse when UI changed, bundle gzip size), and any interpretation you made where the plan was ambiguous. Prefer the simplest interpretation; do not ask mid-task.
- Stop after opening the PR. Do not start the next phase.

## Data rules

- `data/raw/` is read-only input. Everything else in `data/` is generated by scripts and committed.
- `codbairro` is the only identifier used in code and storage. Names are display-only.
- `data/pool.json` is the "conhecidos" subset; "todos" is all bairros minus `data/exclude.json`.

## Style

PT-BR strings by default, kept in one strings file from Phase 4 on. Honest degradation over silent failure: if something can't load, show nothing or a plain message, never a spinner forever. Mobile portrait first (360×640), then desktop.
